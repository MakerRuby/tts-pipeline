# 验收、诊断与交付合规

> 作用：S5 样片评审、S7 QA 的方法与阈值，听感问题的诊断，S8 交付规范与合规检查。
> 不负责：怎么修（见 craft.md），原理（见 principles.md）。
> 读者：执行 skill 的 agent，S5/S7 时与用户共用评审表。
> 更新触发：平台规范或法规变化（S8 前联网核实）；阈值在实践中被证明过严或过松。
> 总原则：**机器抓错，人耳判真。** 自动指标能可靠抓出缺陷，但两段都没有缺陷时，它选不出哪段更像人（arXiv 2609.13150）。

## §样片评审（S5）

**盲听做法（最小可行版）**
- 听众：用户本人，可以再拉 2–5 人。对外宣称"真假难辨"之前，至少要 8–15 人。
- 样本：2–3 个变体，加上同类型的真人参照，按随机顺序编号播放，不告诉听众哪段是什么。所有片段先调到同一响度，否则响的那段会显得更好。
- 每段问两题：① 这是真人还是 AI？② 自然度打几分（1–5）？再请每人写一句"哪里不像"。

**通过标准**：
- 自动检查没有缺陷；
- 至少一个变体被判为真人的比例不明显低于真人参照（小样本时看是否打平或接近）；
- 用户满意。

把结果记进 `qa-log.md`。

## §听感诊断表（S5/S7 不满意时，先定位层，再回到对应阶段）

| 听感描述 | 层 | 回到 | 优先尝试 |
|---|---|---|---|
| 播音腔、念稿感 | L1 | S3 | 拆长句、加"你"、先说结论；换掉新闻腔音色 |
| 情绪不对，或"演过头" | L2 | S3 | 重写意图，删掉多余标签，标签改成更具体的嗓音描述 |
| 平、每句都一个样 | L3 | S3/S6 | 句长交替；关键句单独成句；用段落级抽卡，带前后文 |
| 停顿机械、一样长 | L3 | S3/S8 | 换标点层级；后期微调段间间隔 |
| 读错字、"棒读" | L4 | S4 | **先排查读错**，很多"棒读感"其实是读错了 |

## §AI 味征兆清单（S7 人耳抽听逐项打勾）

来源：McGregor（声学教授）、Vanan、VoiceJungle 等，多来源一致。
- [ ] 静音像被"关掉"，没有房间底噪
- [ ] 声音全程不疲倦，音高和气息没有任何变化
- [ ] 笑声前后没有吸气或收尾
- [ ] 节奏过分整齐，停顿长短一样
- [ ] 每次爆破音、齿音都一模一样
- [ ] 吐字过分清晰，能量范围很窄
- [ ] 单句情绪对，但整段情绪不对
- [ ] 人名、术语读错，重音放错
- [ ] 剪辑点没有过渡
- [ ] 刻意加的"凌乱"（多余的嗯呃、呼吸）听得出来

## §自动闸门（S7）

| 检查 | 工具 | 阈值 | 抓不到什么 |
|---|---|---|---|
| ASR 回检字错率（CER） | `scripts/asr_check.py`；中文转写用 FunASR paraformer-zh，英文用 Whisper large-v3；可以用 SenseVoice 交叉验证 | 整体 CER ≤ 2%；**每条差异都要人工过目**（ASR 自身也会错，也会"脑补纠错"） | 韵律、情绪；同音的多音字误读 |
| 多音字比对 | `polyphone_scan.py` 列出高风险位置，人工抽听；有条件时用 g2pW 标出期望读音，再和转写结果的拼音比对 | 高风险条目 100% 抽听 | — |
| 漏读、重复、串行 | 看 `asr_check.py` 的差异表 | 0 | — |
| 时长 | 实测时长与预算对比 | ±10% 以内 | — |
| 削波、静音 | 后期软件或 ffmpeg 的 `volumedetect` / `silencedetect` | 不能削波；没有超过 2 秒的异常静音 | — |
| 自然度缺陷（可选） | UTMOS / DNSMOS（工具包可用 VERSA，见下） | 只用来找出明显低于同批的离群段 | **不能当作像不像真人的终审** |

**可选工具包 VERSA**（wavlab-speech/versa）
- 六维评估结论：活跃、约 437 star、宽松许可（LICENSE 文件需核对）、Python、部署难度中等、能覆盖 WER/UTMOS/DNSMOS/情感相似度/F0。
- 用法：建独立 venv，只装需要的指标，先用 3–5 段已知好坏的样本冒烟测试，确认分数方向正确。各指标背后的模型权重各有许可证，要分别核对。
- 中文 CER 用本 skill 的 `asr_check.py`，方法借鉴 seed-tts-eval：去标点、繁简统一、编辑距离。seed-tts-eval 没有 LICENSE 文件，所以只借思路，没有用它的代码。

## §交付规范（S8 前联网核实）

| 去向 | 响度 | 峰值 | 其他 |
|---|---|---|---|
| Apple Podcasts | −16 LUFS ±1 | 真峰值 ≤ −1 dBTP | BS.1770 |
| ACX / Audible | RMS −23 到 −18 dB | ≤ −3 dB | 底噪 ≤ −60 dB；44.1kHz、192kbps CBR MP3；一章一个文件，每个不超过 120 分钟；首尾留房间底噪（时长以 ACX 原页为准）。**AI 演播原则上禁止**，例外只有 KDP Virtual Voice 和受邀的 Voice Replica |
| Spotify / YouTube | 播放端会归一化到约 −14 LUFS | −1 dBTP | YouTube 只会把过响的音频调低 |
| 抖音 / B站 / 喜马拉雅 / 课程平台 | 没有官方公开规范 | −1 dBTP | 默认按 −16 LUFS 交付（可在 S1 改成 −14） |
| 数字人平台 | 干净干声，不带配乐 | −1 dBTP | 按平台单段时长上限切分 |

其他 AI 有声书平台（截至 2026-09，二手资料）：Spotify for Authors 接受数字语音，需勾选声明；Kobo 接受，演播者署名写 "Synthesised voice"；喜马拉雅、番茄没有查到公开条文，需要用户登录后台查看。

## §合规

**AI 生成内容标识**（中国《人工智能生成合成内容标识办法》，2025-09-01 施行；配套强制性国标 GB 45438-2025）
- 显式标识：在音频开头、结尾或中间合适位置加语音提示（如"本音频由 AI 合成"），或者加节奏提示（二手资料称是"短长短短"）。可下载的文件也必须带显式标识。
- 隐式标识：在文件元数据里写入 AIGC 属性、服务提供者、内容编号。二手资料称格式是 JSON、字段名为 AIGC，具体以国标原文为准。
  - 写入示例（**仅为示意**，字段名在 S1 对照 GB 45438-2025 原文确认）：`ffmpeg -i in.mp3 -c copy -metadata comment='{"AIGC":{"Label":"1","ContentProducer":"<平台名>","ContentPropagator":"<你的账号>","ProduceID":"<项目-章节号>"}}' out.mp3`
  - 验证：运行 `ffprobe out.mp3`，输出中能看到 comment 字段即可。
  - 有些平台的 API 本身会写水印或元数据（如豆包的 aigc_watermark），这种情况记进 `spec.md`，不要重复写入。
- 发布时主动勾选平台的 AI 声明：抖音、B站都要求，漏标会被补标、退回或下架。不得删除或篡改标识。
- YouTube：逼真的 AI 内容要打开 "AI use" 披露；用自己的克隆声音配音或译制，不需要披露。
- 欧盟 AI Act 第 50 条：2026-08-02 起适用，合成音频要做机器可读标记，deepfake 音频要披露。
- 显式提示放在开头还是结尾，在 S1 和用户确定（会影响听感）。
