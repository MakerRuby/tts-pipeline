# 场景卡（S0 定场景后加载对应一张）

> 作用：写明每个场景在 S0–S9 各阶段要**额外**满足的要求，以及要额外准备的素材。
> 不负责：通用流程（见 SKILL.md）；具体技法（见 craft.md）；平台参数（见 platforms.md）。
> 读者：执行 skill 的 agent。混合场景时同时加载多张卡，冲突项交给用户拍板。
> 更新触发：某场景反复出现同一种返工。
> 素材分级：**必需**指缺了不能开工；**推荐**指缺了能做，但效果或效率下降；**可选**指锦上添花。

---

## A. 科普 / 教学视频解说（单人旁白）

**真人感关键**
- 听起来像老师对着一个学生讲，而不是播音员在念稿。讲解感主要来自稿子：设问、"你看"、先结论后解释。
- 术语读法前后一致。读错一次，信任就会掉一截。
- 节奏跟着信息密度走：新概念出现前停一下，解释时放慢，举例时轻快一些。
- 时长要和画面对齐。后期硬变速超过 ±10% 就能听出来。

**额外素材**

| 级别 | 素材 | 为什么 | 拿不出来时 |
|---|---|---|---|
| 必需 | 定稿或要点，并标出画面切点 | 分段和时长要以画面为准 | 先按段落切，画面定了再对齐，有返工风险 |
| 必需 | 术语表及读法 | 术语读错是最大返工源 | agent 先列出疑似术语，由用户逐条确认 |
| 推荐 | 每个镜头的目标时长 | 写稿时就能控字数 | 按锁定语速估算，留 ±10% 余量 |
| 推荐 | 受众水平（小学、大学、行业） | 决定口语化程度和讲解深度 | 默认按"聪明的外行"来写 |
| 可选 | 系列风格指南，或 video-learning-workflow 的 series-bible | 多期之间保持一致 | 第一期产出后反向沉淀成风格指南 |

**各阶段额外要求**
- S1：只要涉及控时长，就优先选能指定时长的模型（如 IndexTTS 的 duration_factor）或支持语速参数的平台。
- S3：设计语速时按 `craft.md` 的中文语速表，解说一般取中速。每个新术语第一次出现时，前面可以停顿约 0.3 秒，后面跟一句解释。
- S5：样片要包含"最密集的那段公式或术语"。
- S8：交付时同时给出逐段时长表，以及 ASR 回转出来的字幕（SRT），方便剪辑对齐。

**典型返工**：配音比画面长（写稿时就算字数）；同一术语前后读法不一（S4 统一，入词典）；播音腔（脚本太书面，或选了新闻类音色，回到 S3 或 S2 修改）。

**与 video-learning-workflow 衔接**：脚本和教学设计在那个 skill 里定稿后，再进本 skill 的 S3。画面时长以它的分镜为准。

## B. 有声书 / 长篇叙事

**真人感关键**
- 长时间听下来音色稳定。漂移是长篇最大的问题，一般每 2 分钟左右就可能出现一次。
- 旁白和对白要分开处理；角色音色有区分，而且全书一致。
- 情绪有弧线：只在情节转折处加标注，不要每句都演。
- 句间停顿和换气自然，章节首尾留出房间底噪。

**额外素材**

| 级别 | 素材 | 为什么 | 拿不出来时 |
|---|---|---|---|
| 必需·**开工硬条件** | 有声改编权证明，或本人作品声明 | 平台审核与法律风险 | 不能发布，只能自用（需用户书面确认） |
| 必需 | 全文电子稿，按章分好 | 分章生产与 QA | agent 按标题自动分章，用户确认 |
| 必需·**开工硬条件** | 目标发布平台 | 不同平台对 AI 演播的政策差别很大（如 ACX 原则上禁止）；S1 要据此核实政策 | 先查政策再开工，避免整本书做完不能上架 |
| 推荐 | 角色表：性别、年龄、性格、口头禅、关系 | 角色音色设计与区分 | agent 从文本中抽取后请用户确认 |
| 推荐 | 人名、地名读音表 | 长篇里会重复出现成百上千次 | S4 扫描后请用户确认 |
| 可选 | 每个角色的参考音色样本 | 克隆或选音色更快 | 用 Voice Design 生成候选 |

**各阶段额外要求**
- S1：问清楚要配几个音色。默认是"旁白 1 个 + 每个主要角色 1 个"。
  - 主要角色指全书对白超过约 30 句，或在关键情节里出现的角色。
  - 次要角色共用 2–3 个"路人音色"，按性别和年龄分。
  - 再核实所选平台能否同时稳定支持这么多音色。
- S2：每个主要角色一张说话人卡，旁白另有一张。角色之间在音高、语速、质感这三项里，至少要有两项明显不同。
- S3：**不跑 P1，原文锁定。** 作者的文字就是作品本身，改写会碰到改编权和作品完整性问题。
  - 只做数字和符号的归一化，写入 `01_spoken.md`。确实要改字时（例如生僻字换成同音字），逐处列出，取得作者或权利人同意，并记入 `decisions.md`。
  - 先用 P2 的"说话人标注"模式，标出每句是旁白还是哪个角色、带什么情绪；用户按章抽查校对后，再做表演标注。
  - 对白前"他颤抖着说"这类提示语属于原文，必须保留，让模型照常念出来。这类提示本身也能帮模型把握情绪。
- S5：样片选 3 段：开篇旁白、多人对白、情绪高潮。
- S6：分段以场景或自然段为单位；每章生成完马上抽查音色漂移。
- S7：每章跑一次 ASR 回检，原文用 `script/chNN/02_directed.md`；抽听位置按 SKILL.md S7。
- S8：一章一个文件，首尾留房间底噪；按平台规格交付（ACX 等规格见 `qa-delivery.md`）。

**典型返工**：中途换音色导致前后不一（S2 锁定；必须换时，整个角色全书重做）；说话人标错导致串音（S3 先校对说话人标注）；响度不达标被平台退回（S8 跑交付检查）；做完才发现平台不收 AI 演播（S0 先查政策）。

## C. 播客 / 多人对话

**真人感关键**
- 脚本里的自发细节，和 TTS 模型本身同等重要（MoonCast 的结论）：附和、插话、犹豫、笑。
- 轮次节奏：真人换人说话几乎没有空档，偶尔还会重叠；长短轮次交替出现（研究依据见 `principles.md` L7，拼接数值见 `craft.md` §对话）。
- 两人的角色功能不同：一个懂、一个问；或者观点有分歧。只为热闹而加的第二个人会显得假。
- 能整段生成就不要逐句拼接。逐句拼接的轮次间隔太均匀，听起来机械。

**额外素材**

| 级别 | 素材 | 为什么 | 拿不出来时 |
|---|---|---|---|
| 必需 | 源材料（文章、论文、提纲） | 对话内容的事实来源 | 只给主题时，agent 起草，用户核对事实 |
| 必需·**开工硬条件** | 源材料的授权情况：作者本人、CC BY 等开放许可，或出版社版权 | 把别人的论文或文章改编成播客发布，属于演绎使用 | 版权不明时只讲观点、不大段复述，并注明出处；风险由用户拍板 |
| 必需 | 主持人人设（2 人起），包括知识水平和关系 | 决定谁问谁答、语气和互动方式 | 默认"懂行的主讲 + 好奇的提问者" |
| 必需 | 一段 1–2 分钟的真人**两人对话**播客片段，作为真人参照 | S2/S5 要拿它比对轮次节奏和附和方式；单人录音没有参照价值 | agent 推荐几个同类中文播客，用户从中截一段 |
| 推荐 | 每位主持人的音色样本和授权 | 音色区分与一致 | 从平台音色库选两个差异大的 |
| 推荐 | 目标时长、听众水平、禁区话题 | 控制篇幅与边界 | 默认 8–12 分钟、聪明的外行 |

**各阶段额外要求**
- S1：优先选原生多人对话的模型或端点（见 `platforms.md` §1 决策树第 2 条）。中文常见选择有豆包播客、MOSS-TTSD、FireRedTTS-2；英文常见选择有 ElevenLabs Text to Dialogue、Dia2。
- S3：**用 P5 代替 P1。**
  - 先给 `00_source.md` 按段落编号，格式为 `【段1】` `【段2】`……
  - 再用 P5 写对话脚本，密度按 `craft.md` §对话，写入 `01_spoken.md`。
  - 然后用 P2 做平台语法标注。
  - 不跑 P6：从论文压缩成对话，内容必然有删减，逐句比对没有意义。事实核对以 P5 输出的事实核对表为准，要求每个事实点都能追溯到源段号，而且含义没有失真。
- S5：样片必须包含一次插话和至少 3 次附和。
- S6：按"话题段"整段生成；只能逐句合成时，后期按 `craft.md` 的轮次间隔表重排间隔，不要用固定值。
- S7：重点抽查说话人是否串音、轮次是否错乱、附和是否过密。

**典型返工**：串音或轮次错乱（选轮次可靠的模型，按段生成）；附和过密显得做作（控制密度）；事实错误（对照源材料核对）；为了"张力"硬造分歧（只在材料本身有争议时才用辩论格式）。

## D. 数字人口播 / 实时语音

分成两个子场景，S0 时问清楚是哪一个。

### D1 数字人口播（预渲染，对口型）

**真人感关键**：音频干净，背景音乐等对完口型以后再混；语速适中，过快时口型跟不上；TTS 的情绪要和画面表情、动作一致，不一致会掉进恐怖谷；分段不能超过数字人平台的时长上限。

**额外素材**

| 级别 | 素材 | 为什么 | 拿不出来时 |
|---|---|---|---|
| 必需 | 口播稿 | — | agent 起草 |
| 必需 | 数字人平台及其单段时长上限（以当前界面为准） | 决定怎么切段 | 先联网查，再请用户确认 |
| 必需·**开工硬条件** | 形象与声音的肖像授权、声音授权 | 法律风险 | 只能用平台自带形象和音色 |
| 推荐 | 每段对应的表情和动作意图 | 让声音情绪和画面对齐 | 默认用平和、亲切的基调 |

**额外要求**：S3 按上限切段，切点放在句号处；S8 交付干声（不带背景音乐），背景音乐在数字人平台生成视频后再混。

### D2 实时语音助手

**真人感关键**：嘴到耳的总延迟目标约 1.1 秒，超过约 0.8 秒用户就能察觉；能被用户打断，并且能区分打断、附和和噪音；回复要短、口语化、像在说话（让 LLM 输出口语）。

**额外素材**：网络形态（电话还是 WebRTC）、延迟目标、是否必须支持打断、对话场景和人设。

**额外要求**：
- S1：先在级联方案（STT + LLM + TTS，可替换、好调试）和端到端方案（延迟低）之间做选择。
- S3：改成写 LLM 的"口语输出风格提示词"，不再写固定稿。
- S5：改成延迟预算表，逐项测量 STT、LLM 首 token、TTS 首包。
- S7：加打断测试，监控两项指标：误打断率（参考值 8% 以内）和抢话率（参考值 5% 以内）。
- 本场景**不适用**的阶段：S6 的抽卡、S8 的大部分后期。

**典型返工**：音频超过平台上限被截断（先切段）；口型对不上（音频不干净或语速过快）；实时助手误打断（调 VAD 和端点检测）；延迟超标（逐项测量，不要只靠开流式）。
